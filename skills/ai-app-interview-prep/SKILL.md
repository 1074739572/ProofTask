# AI 应用开发秋招面试准备（Java + Python 双方向）

为 AI 应用开发工程师（LLM 应用 / Agent / RAG 方向，Java + Python 技术栈）提供一套可执行的秋招面试准备方法论。设计目标是：**能让用户把简历上写的每个字都经得起面试官三轮追问，并在技术面上覆盖 AI 应用 + Java 后端 + Python 工程三大块。**

## 什么时候用

- 用户说「秋招」「面试」「八股」「背题」「模拟面试」「项目深挖」时立即启用。
- 用户说「看看我的简历哪里会挂」「这个技术点怎么说」时启用。
- 面试前一天/前一周做冲刺复习时启用。

## 工作模式

| 模式 | 触发 | 产出 |
|---|---|---|
| 简历雷达 | 用户贴简历/提到简历 | 从面试官视角列出会被追问的点 + 时间线/真实性检查 |
| 考点速刷 | 用户说某技术点 | 该点的「一句话答案 + 追问清单 + 彩蛋问题」 |
| 项目深挖 | 用户说某个项目 | 按「痛点→机制→价值→降级→验证」五段式打磨讲解稿 |
| 模拟面试 | 用户要求模拟 | 分轮提问（基础→深挖→设计→反问），给评分与改进点 |
| 八股清单 | 用户要过八股 | 按本章节清单逐条自测，标出记不住的 |

## 一、简历雷达（先用它）

### 1.1 时间线真实性检查（第一优先级）

- 实习/项目时间与教育背景衔接是否自洽（例：实习年份 vs 入学年份）。
- 同一时段项目数量是否多到不可信——**宁可 3 个精品，不要 6 个凑数**。
- 每个项目必须有：时间、角色、团队规模、个人职责、1-2 个真实数字。

### 1.2 面试官视角查漏

对简历逐行问三个问题：

1. **「这是你一个人做的还是团队？」**——每条亮点必须能说出「我独立负责哪块、协作方是谁」。
2. **「这个数字哪来的？」**——每个数字必须能讲清来源与口径，讲不清就删。
3. **「这个名词你能讲几轮？」**——技能表里的每个词，用户必须能扛住 3 轮追问，扛不住就砍。

### 1.3 输出格式

```
## 简历体检报告
- 🟢 能打项（保留并强化）
- 🟡 会问但需补素材项（给出补法）
- 🔴 会挂项（时间线/失真/无法解释的数字）→ 给出改法
```

## 二、AI 应用核心考点（本 skill 的主战场）

### 2.1 RAG 全链路（面试必考）

逐环节准备「一句话 + 追问 + 降级」：

| 环节 | 一句话答案 | 必问追问 | 降级/彩蛋 |
|---|---|---|---|
| 文档解析 | 多格式解析出正文/标题/表格/页码 | 扫描件怎么处理？表格结构怎么保留？ | OCR + 版面分析；失败重试 |
| 分块（chunk） | 父子分块：小块命中、大块理解 | 块多大？重叠多少？为什么父子两级？ | 语义完整 vs 检索精度权衡 |
| 嵌入（embedding） | 向量化文本供语义检索 | 用什么模型？维度？中文效果？ | 领域微调 vs 通用模型 |
| 混合检索 | 稠密向量 + BM25 稀疏互补 | 怎么融合？权重怎么定？ | 各通道超时/异常隔离 |
| 重排（Rerank） | 交叉编码器精排候选 | 从多少精排到多少？为什么？ | 精排异常降级保留融合结果 |
| 引用/证据 | 只展示模型实际用的证据编号 | 怎么校验引用是模型真用过的？ | 无证据拒答；预算约束 |
| 评估 | 检索命中率/答案准确率/幻觉率 | 评估集哪来的？多少条？ | 影子观测 + 线上 Trace |

### 2.2 Agent 编排（第二必考）

- Tool Calling：工具定义、参数校验、模型与代码谁做决定。
- 上下文记忆：长短期记忆分离、会话级 vs 跨会话持久化。
- 任务拆解：原子单元 + 依赖图 + WIP=1，防目标漂移。
- 多 Agent 协作：消息总线/收件箱异步通信、子 Agent 独立上下文、只回传摘要。
- **状态与刹车**：显式状态机、硬停止条件（超时/重试/无进展）、断点续跑。
- **完成判定外部化**：机器验证 > 状态机 > 独立评估 > 自报（agent 自报无程序效力）——这是能讲出「设计深度」的点。

### 2.3 Text2SQL（若有项目）

- 语义匹配：问题→SQL 的转化、实体白名单终审、「猜错转问清」闭环。
- 数值可信：BigDecimal 防精度丢失、溢出防护、格式稳定。
- 图表渲染与建议解耦：模型只出类型建议，字段映射按列类型推断。

### 2.4 Agent 评估（简历要求「加一个 Agent 评估」）

- 离线评测集 + 指标（完成率、越界率、端到端通过率）。
- 线上影子观测 + Trace 日志沉淀。
- 对照实验要能说清：对照组是什么、变量是什么。

## 三、Java 方向考点清单

### 3.1 Java 基础与并发

- HashMap/ConcurrentHashMap 底层与扩容；synchronized/volatile/AQS。
- 线程池参数与拒绝策略；CAS 与 ABA；ThreadLocal 内存泄漏。
- JVM：内存分区、GC 算法与收集器、OOM 排查。

### 3.2 Spring Boot / Spring AI

- IoC/AOP 原理；Bean 生命周期；自动装配原理。
- Spring AI：ChatClient、Tool Calling、结构化输出、RAG 组件。
- 事务传播行为与失效场景。

### 3.3 MySQL / Redis / MQ

- **MySQL**：索引结构（B+Tree）、执行计划（EXPLAIN）、索引失效场景、锁与隔离级别、慢 SQL 优化套路（可讲实习里 1500% CPU 故障排查案例）。
- **Redis**：缓存穿透/击穿/雪崩、分布式锁（Redisson）、持久化、淘汰策略、幂等方案（可讲 Token + AOP 幂等案例）。
- **MQ（RabbitMQ/Kafka）**：消息可靠性（生产/存储/消费）、死信队列、顺序性、削峰填谷（可讲实习里 DLQ + 削峰案例）。

## 四、Python 方向考点清单

### 4.1 语言与工程

- GIL、迭代器/生成器、装饰器、上下文管理器、asyncio 与 FastAPI 异步接口。
- 类型注解、Pydantic 校验、依赖注入。

- Transformer 架构（注意力、位置编码、多头）；MLP/CNN 基本概念。
- 微调：LoRA vs 全参；过拟合与正则化；评估指标（精确率/召回/F1）。

### 4.3 LangChain / LangGraph 生态

- LangChain 核心组件（LCEL、Retriever、Tool）；LangGraph 状态图与节点编排。
- 与直接调用 API 的取舍：什么时候该用框架、什么时候手写。

## 五、项目深挖（五段式讲解）

对简历上每个项目，按下面模板打磨出一段 60-90 秒的讲解稿 + 3 层追问答案：

```
1. 痛点：这个系统解决什么真实问题？之前方案为什么不行？
2. 机制：核心设计是什么？为什么这么设计？（讲 1-2 个关键决策）
3. 价值：带来什么可度量结果？（1-2 个真实数字）
4. 降级：关键环节失败时怎么兜底？（降级路径 = 面试加分点）
5. 验证：怎么证明它有效？（评测/对照/线上数据）
```

**深挖三连问（必答）**：
- 「如果数据量翻 10 倍，你的方案哪里先崩？」
- 「你踩过最大的坑是什么？怎么排查的？」
- 「这个设计你跟别人讨论过吗？有没有被否掉的方案？」

## 六、模拟面试

### 6.1 流程

1. 先问用户：目标岗位（AI 应用/后端/算法）、时长（30/45/60 分钟）、要哪部分（技术/项目/综合）。
2. 分轮提问：
   - 轮 1 基础八股（5 题，从三/四章挑）
   - 轮 2 项目深挖（随机抽 1 个项目走五段式追问）
   - 轮 3 场景设计（如「给一个 10 万文档的 RAG 系统做检索优化」「给 Agent 加评估」）
   - 轮 4 反问环节（教用户怎么反问面试官）
3. 用户回答后逐题给**评分 + 参考答案要点 + 改进建议**，不要只给答案不点评。

### 6.2 反问环节推荐问题（面试官视角会加分）

- 「这个岗位现在最头疼的 AI 应用问题是哪个？」
- 「团队现在 RAG/Agent 落地到哪个阶段了？评估怎么做？」
- 「进去前三个月预期产出是什么？」

---

## 七、八股清单自测法

- 逐项过三/四章清单，用户答不出/模糊的标 🔴，记入本轮「待补清单」。
- 每轮结束输出：《待补清单》+ 用户已掌握项，下次从上轮待补开始。
- 冲刺日（面试前 3 天）：只过 🔴 项 + 项目五段式口头演练。

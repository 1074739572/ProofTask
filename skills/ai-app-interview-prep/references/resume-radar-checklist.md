# 简历雷达 · 面试官检查清单

面试官拿到简历后 60 秒内会做的事：扫时间线 → 数项目 → 盯数字 → 记要追问的名词。
本清单按这个顺序帮用户自查。

## 1. 时间线（一票否决项，先查）

- [ ] 实习年份是否与教育阶段衔接自洽（本科实习 vs 硕士实习不能混）
- [ ] 是否有「在读期间同时做 4+ 个完整项目」的堆砌感
- [ ] 项目时间是否与毕业时间冲突（还没毕业但项目持续到毕业后）
- [ ] 每个项目都有明确的起止时间与角色

## 2. 项目数量与选择

- [ ] 精选 2-3 个主项目（大于 3 个会稀释可信度）
- [ ] 项目间亮点是否有重叠（重叠的合并或砍掉弱的）
- [ ] 是否有差异化主打项目（如 Harness/Text2SQL 作为招牌）
- [ ] 每个项目第一句能回答「团队还是个人、我负责哪块」

## 3. 数字核验

- [ ] 每个数字都能说清来源（评测/日志/线上数据）
- [ ] 数字不与现实矛盾（如「支持并发 10 万」但无任何依据）
- [ ] 关键效果有对比基线（优化前 vs 优化后、约束 vs 无约束）
- [ ] 数字表述一致（别处写 98%，这里写 100%，面试官会抓住）

## 4. 技能表（会被逐词追问）

- [ ] 每个名词能扛 3 轮追问（是什么 → 原理 → 你项目里怎么用）
- [ ] 技能总数控制在 6-8 个能深聊的项，不堆砌
- [ ] AI 方向（RAG/Agent/Tool Calling）与后端方向（Java/MySQL/Redis）比例均衡
- [ ] 专有名词（如「五通道」「WIP=1」）只在项目里用，不进技能栏

## 5. 面试官最容易深挖的「证明你是真做过」点

- [ ] 关键环节的失败/降级路径能讲出（链路挂了你怎么兜底）
- [ ] 能讲出「踩过的坑」和排查过程（比成功的点更可信）
- [ ] 能讲出「被否掉的方案 / 为什么不用另一个方案」——证明有取舍
- [ ] 简历上没有的边界情况也准备过（数据量 10 倍、并发、异常输入）

## 用法

- 每轮改简历后跑一遍，凡有未勾选项就当场改/补素材。
- 本项目文件与 SKILL.md 联动：简历雷达模式就是「按此清单逐项核 + 输出 🟢🟡🔴 报告」。
